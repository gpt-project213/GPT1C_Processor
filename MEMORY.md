# MEMORY

Каноническая краткая память проекта в корне репозитория.
Если правило, решение или важный итог нужен для будущих сессий, он должен быть зафиксирован здесь или в `PROJECT_ENCYCLOPEDIA.md` / `SESSION_CONTEXT.md`.

## Правила пользователя

- Никакой лжи, имитации и выдуманных подтверждений.
- Отвечать жёстко и прямо там, где код однозначен.
- `Молчание` в дебиторке для бизнеса означает отсутствие оплаты, а не отсутствие переписки.
- Несколько адресов с одним телефоном у одной хозяйки не считать автоматическим дублем.
- Всё важное по проекту хранить в корне проекта, а не только во внешней памяти инструмента.

### 2026-05-19 — CRM same-client confirm

- Повторный вопрос менеджеру по `Орлову` / `Садко` был не из-за потери CRM-state, а из-за новых CRM-ключей, которые система воспринимала как новых клиентов.
- Правильное решение для CRM:
  - не автосклеивать похожие карточки
  - сначала спросить менеджера: `Это один и тот же клиент?`
  - если `Да` -> связать новый ключ с существующей карточкой как alias и унаследовать ownership
  - если `Нет` -> пометить пару как разные и только потом запускать обычную идентификацию
- Это относится к основному боту / CRM-контуру, не к напоминалкам.
- `claim_broadcast` в таких кейсах должен быть fallback, а не первый шаг.
- Для confirmed different-pair нужно сохранять исключение, чтобы тот же вопрос не повторялся бесконечно.

Текущий рабочий слой поверх `0fbbaba`:

- В `bot/crm_clients.py` добавлены публичные helper'ы:
  - проверка исключённой пары
  - merge нового ключа в существующую карточку
