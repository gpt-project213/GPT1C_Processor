### Находки

#### AUDIT-2026-04-21-001 (D, low) — cmd_analytics для unknown: тихий no-op вместо «⛔ Доступ запрещён»
- **Файл:** `bot/send_reports.py:6833–6851`
- **Evidence:** `cmd_analytics` не вызывает `_acl_gate`; логика основана только на `_build_analytics_kb(user_role)`, которая для role="unknown" возвращает None → `return` без сообщения пользователю. Другие entry-points (cmd_start, cmd_guide, handle_persistent_menu) через `_acl_gate` пишут «⛔ Доступ запрещён».
- **Reproducer:** `/analytics` от незарегистрированного chat_id — пустая реакция, у пользователя ощущение зависшего бота.
- **Impact:** минорная UX-несогласованность. Не security (no-op корректный), но поведение расходится с остальными командами.
- **Fix proposal:** добавить `if not await _acl_gate(chat_id, context): return` перед `user_role = get_user_role(chat_id)`.

#### AUDIT-2026-04-21-002 (D, low) — cmd_expenses: callback ветка без answer() для unknown
- **Файл:** `bot/send_reports.py:6854–6863`
- **Evidence:** для user_role не в {admin, subadmin} ветка `if update.callback_query: await update.callback_query.answer("⛔ Доступ запрещён")` работает, но если команда вызвана как `/expenses` (message-ветка) — return без сообщения. Менеджер при попытке выполнить `/expenses` получит тишину.
- **Impact:** менеджер не понимает, почему бот не отвечает.
- **Fix proposal:** добавить `else: await _send_auto(context, chat_id, "⛔ Доступ запрещён.")`.

#### AUDIT-2026-04-21-003 (E, low) — handle_voice_message_tg: unknown без уведомления
- **Файл:** `bot/send_reports.py:7224–7236`
- **Evidence:** для `get_user_role == "unknown"` return без сообщения. Voice от unknown — тишина. Консистентно с cb_data, но отличается от handle_persistent_menu (через `_acl_gate` шлёт «⛔»).
- **Impact:** UX-консистентность.
- **Fix proposal:** либо привести все unknown-entry к одному паттерну (рекомендую `_acl_gate` везде), либо документировать разницу.

#### AUDIT-2026-04-21-004 (C, medium) — _is_pid_running: fail-safe возвращает True, но без различения PID vs бинарь
- **Файл:** `bot/send_reports.py:283–296`
- **Evidence:** проверка через `tasklist /FI "PID eq {pid}"` — если Windows после рестарта переиспользовал PID под другой процесс (например cmd.exe), `_check_single_instance` решит что бот уже запущен и **завершится с exitcode=1**. Отдельного matching по имени процесса нет.
- **Reproducer:** убить процесс бота без cleanup PID-файла → дождаться переиспользования PID системой → перезапуск упадёт с «Бот уже запущен».
- **Impact:** false-positive блокировка старта, особенно после принудительных kill.
- **Fix proposal:** дополнить tasklist фильтром по `/FI "IMAGENAME eq python.exe"` и подгрузить результат, либо сохранять в PID-файле строку `"{pid}|{python_exe}"` и сверять полностью.

#### AUDIT-2026-04-21-005 (B, medium) — _crm_save_pending: fixed-name .tmp → race при параллельной записи
- **Файл:** `bot/send_reports.py:5161–5172`
- **Evidence:** `tmp = CRM_PENDING_PATH.with_suffix(".tmp")` даёт **одну и ту же** строку для всех писателей. Два coroutine (разные менеджеры одновременно завершают clarify) могут одновременно открыть этот файл — второй писатель перезапишет tmp, итоговый `.replace()` коммитит частично обновлённое состояние. Остальные пути (`_save_json_atomic`, `_save_weekly_clients`) используют `NamedTemporaryFile` с уникальным именем.
- **Reproducer:** два менеджера вызывают `/phone` и оба завершают 3-й шаг clarify_address в одну миллисекунду.
- **Impact:** потенциальная потеря state одного из pending. Редкий, но реальный в момент пика 18:00 daily CRM.
- **Fix proposal:** заменить на `NamedTemporaryFile("w", delete=False, dir=CRM_PENDING_PATH.parent, suffix=".tmp")` + `os.replace(tmp.name, CRM_PENDING_PATH)` — шаблон как в `_save_json_atomic`.

#### AUDIT-2026-04-21-006 (E, medium) — pipeline_task: glob `*.xls*` захватит `.xlsx.work`
- **Файл:** `bot/send_reports.py:3467`
- **Evidence:** `QUEUE_DIR.glob("*.xls*")` матчит `foo.xlsx`, `foo.xls`, а также `foo.xlsx.work` (суффикс расширения — `*`). По CLAUDE.md, `.work` ставит `run_pipeline_all_mp.py` при ручном запуске; бот pipeline_task не использует `.work`, но если оператор запустил CLI параллельно или предыдущий сеанс бота упал с `.work`-файлом — следующий tick ПОТЕРЯЕТСЯ/ЗАЦИКЛИТСЯ на `.work`.
- **Reproducer:** подложить `reports/queue/test.xlsx.work` → наблюдать `file_processing_error` каждые 10 минут.
- **Impact:** потенциальный бесконечный цикл ошибок в pipeline, забивание логов.
- **Fix proposal:** изменить glob на `*.xls` + `*.xlsx` отдельными вызовами, либо добавить фильтр `if p.suffix.lower() in (".xls", ".xlsx")`.

#### AUDIT-2026-04-21-007 (D, low) — kb_main(unknown) возвращает пустой InlineKeyboardMarkup
- **Файл:** `bot/send_reports.py:2943–2980`
- **Evidence:** для `user_role` вне admin/subadmin/manager → `rows = []` → `InlineKeyboardMarkup([])`. Telegram при попытке `send_message(reply_markup=<empty markup>)` возвращает BadRequest. `send_main_menu` ловит Exception, но это тихий silent failure.
- **Impact:** мёртвый путь, но если какой-то новый code path достигнет `send_main_menu(..., "unknown")` — тихий сбой.
- **Fix proposal:** `if user_role not in ("admin", "subadmin", "manager"): return None` + проверка в вызывающих.
