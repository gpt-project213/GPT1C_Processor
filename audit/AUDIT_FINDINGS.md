# AUDIT_FINDINGS

## Метод и рамки

Аудит выполнен без изменения рабочей логики. Проверены код, доступные конфиги, snapshot state/json, публичные runtime-логи, тестовые сценарии.

## Реестр находок

### F-001 — Отсутствуют ключевые runtime-конфиги в snapshot
- Статус: **Требует дополнительного подтверждения**
- Критичность: **Высокая**
- Контур: Config / Access / Routing
- Подтверждение: код прямо зависит от `config/managers.json`, `config/roles.json`, `config/imap.json`, `.env`; в репозитории доступны только `pattern_config.yaml` и `weekly_clients.json`.
- Влияние: невозможно доказать корректность ролей, chat_id, whitelist, scopes и части cron-веток на данном snapshot.

### F-002 — IMAP фильтрация может делать «тихий» drop вложений
- Статус: **Работает, но с риском**
- Критичность: **Высокая**
- Контур: IMAP / Queue
- Механизм: при `REQUIRE_MANAGER_IN_NAME=true` и отсутствии manager name в filename вложение пропускается; часть логов на DEBUG.
- Подтверждение: `imap_fetcher.py` + runtime `SKIP no-manager-in-name`.
- Влияние: система выглядит активной (цикл идёт), но часть полезных файлов не попадает в pipeline.

### F-003 — Pipeline фиксирует активность, но не всегда полезный результат
- Статус: **Работает, но с риском**
- Критичность: **Высокая**
- Контур: Queue / Pipeline / Runtime
- Механизм: `run_script_finish rc=0` не означает доставку результата; для некоторых типов пустой output трактуется как допустимый.
- Подтверждение: `run_pipeline_all_mp.py` (outs==[] для non-DEBT), логи send_reports с большими сериями `run_script_finish`.
- Влияние: ложная видимость «всё ок» при отсутствии конечного бизнес-эффекта.

### F-004 — Telegram доставка частично деградирована (`Chat not found`)
- Статус: **Работает частично**
- Критичность: **Высокая**
- Контур: Telegram bot / Delivery
- Подтверждение: repeated `Chat not found` в runtime-логах.
- Влияние: часть менеджеров не получает уведомления/документы.

### F-005 — Тестовый контур проекта не проходит в текущей среде
- Статус: **Работает частично**
- Критичность: **Средняя**
- Контур: CI-like confidence / deps
- Подтверждение: `tests/test_project.py` падает на `ModuleNotFoundError: requests`; также warning о `managers.json not found`.
- Влияние: нет полного подтверждения работоспособности non-collector контура на текущем окружении.

### F-006 — Collector модуль функционален, но сильно state-driven
- Статус: **Работает, но с риском**
- Критичность: **Средняя**
- Контур: AI Collector / Manager Dialog
- Подтверждение: `tests/test_collector.py` 104/104 passed; в коде `already_contacted_today`, promise/escalation flags, pending states.
- Влияние: stale state может блокировать повторные отправки или приводить к зависшим веткам до ручного вмешательства.

### F-007 — Debt Stop контур реализован, но доказательство runtime неполное
- Статус: **Не доказано**
- Критичность: **Средняя**
- Контур: Debt Stop / Registry
- Подтверждение: кодовая реализация есть (jobs, state/registry), но оригинальные runtime state-файлы в snapshot отсутствуют.
- Влияние: нельзя подтвердить реальное прохождение всех веток эскалации/финального списка.

### F-008 — Snapshot state-файлы в `logs_public` непарсибельны
- Статус: **Требует дополнительного подтверждения**
- Критичность: **Средняя**
- Контур: Registry / State / Runtime auditability
- Подтверждение: `notify_state.json`, `deletion_queue.json` в snapshot содержат редактированные placeholder-значения и не парсятся JSON.
- Влияние: часть утверждений о последовательности state-переходов невозможно закрыть доказательно без оригиналов.

### F-009 — Контур PDF в рабочем потоке не подтверждён
- Статус: **Не работает**
- Критичность: **Низкая**
- Контур: Report outputs
- Подтверждение: поиск по проекту не выявил активного генератора/отправки PDF; эксплуатационный поток ориентирован на HTML/JSON.
- Влияние: требования на PDF (если обязательны) не закрыты текущей системой.

### F-010 — Двойная оркестрация pipeline повышает операционный риск
- Статус: **Работает, но с риском**
- Критичность: **Средняя**
- Контур: Scheduler / Runtime
- Подтверждение: есть и `run_pipeline_all_mp.py`, и встроенный `pipeline_task` в `send_reports.py` (каждый умеет IMAP+processing).
- Влияние: при неконсистентном запуске возможны дубли/перекрытия ожиданий по маршрутизации и диагностике.

## Что подтверждено штатно

- Базовый startup бота и scheduler registration.
- IMAP забор и сохранение вложений в queue + clean copy.
- Запуск report/parser scripts по всем основным типам.
- Collector unit/regression тест-контур.

## Что не подтверждено на snapshot

- Реальный runtime state debt_stop/collector/notify в неизменённом виде.
- Корректность ACL/roles/scopes в production-подобной конфигурации.
- Полнота доставки всем целевым chat_id.
