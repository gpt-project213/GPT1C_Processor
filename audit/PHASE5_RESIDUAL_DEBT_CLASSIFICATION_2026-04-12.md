# PHASE 5 — классификация по возрасту текущего остатка долга

Автор: Codex
Дата: 2026-04-12

## Проблема

Коллектор использовал `days_silence` как основной возраст долга.
В отчетах из `debt_auto_report.py` это не возраст текущего остатка, а тишина с последней оплаты.

Пример: `А ТД Шапагат 5 павильон Дюсембина`.

- Долг: 64 415.36 тг
- `days_silence`: 19
- Реальный остаток состоит из свежих отгрузок:
  - 2026-04-08: 28 084.00 тг
  - 2026-04-10: 36 331.36 тг

Старая строка `L2 | 19д` выглядела так, будто текущий долг старый на 19 дней. Это было неверно.

## Проверка источника данных

Перед реализацией прочитан `debt_auto_report.py`.

Вывод:

- `clients[].movements` хранит только количество движений.
- Настоящие движения с датами лежат в `blocks[].movements`.

Поэтому `collector.debt_monitor.load_latest_debt_json()` теперь подцепляет `blocks[].movements` к клиентам как `_movements`.

## Что изменено

Добавлен расчет `compute_residual_debt_profile()`.

Принцип:

1. Долг на начало периода ставится первым в очередь.
2. Отгрузки добавляются в очередь по датам.
3. Оплаты закрывают самые старые неоплаченные суммы первыми.
4. Возраст долга считается от самой старой оставшейся неоплаченной части.

Если движений с датами нет, поведение остается прежним: fallback на `days_silence`.

## Какие метрики теперь есть

Классификатор хранит две разные цифры:

- `residual_debt_age_days` — возраст текущего остатка, по нему определяется уровень L0-L5.
- `payment_silence_days` — сколько дней не было оплаты, справочно для менеджера.

Дополнительно сохраняется:

- `oldest_unpaid_date`
- `unpaid_parts`
- `debt_age_basis`
- `debt_age_confidence`
- `active_turnover`

## Политика first_seen

Старый счетчик `first_seen` теперь не повышает уровень, если возраст долга уже посчитан по движениям.

То есть при `debt_age_basis = movements_fifo`, `opening_fallback` или `no_debt` уровень остается по реальному остатку.

Это важно, чтобы свежий долг не стал снова L1/L2 только потому, что клиент раньше уже попадал в state.

## Что увидит менеджер/админ

Вместо:

`Просрочка: 19 дн.`

Теперь:

`Возраст остатка: 3 дн. · Остаток с: 2026-04-08`

Так видно главное для коллектора:

- текущий остаток свежий;

`payment_silence_days` остается во внутренних данных для аудита, но не выводится в менеджерский текст, чтобы фраза "оплат нет X дней" не воспринималась как возраст текущего долга.

## Доказательство на Шапагате

Проверка на реальных данных показала:

- Клиент: `А ТД Шапагат 5 павильон Дюсембина`
- Уровень: L0
- Возраст текущего остатка: 3 дня
- Оплат нет: 19 дней
- Основа расчета: `movements_fifo`
- Самая старая неоплаченная часть: 2026-04-08
- Остаток:
  - 2026-04-08: 28 084.00 тг
  - 2026-04-10: 36 331.36 тг

## Что важно перед понедельником

Перед controlled live test все равно запускать понедельничный precheck и preview по Phase 3 runbook.

Эта правка меняет качество классификации, но не отменяет безопасную цепочку:

preview -> manager approve -> admin approve -> send-approved.
