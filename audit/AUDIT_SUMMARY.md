# AUDIT_SUMMARY

## Executive Summary

Статус проекта: **частично готов к эксплуатации**.

Подтверждённые рабочие контуры:
- IMAP → очередь → pipeline (циклы выполняются, файлы сохраняются, clean-копии создаются).
- Генерация HTML/JSON по основным типам (debt/sales/gross/inventory/expenses) по коду и runtime-логам.
- Планировщик Telegram-бота (APScheduler) поднимается, джобы регистрируются, polling запускается.
- AI Collector-модуль и manager dialog FSM присутствуют, тестовый контур коллектора проходит.

Критичные ограничения и риски:
- В репозитории отсутствуют ключевые runtime-конфиги (`config/managers.json`, `config/roles.json`, `config/imap.json`, `.env`) — часть контуров не может быть доказана на предоставленном снимке.
- Тест проекта (`tests/test_project.py`) падает из-за отсутствия зависимости `requests` и отсутствия `managers.json`.
- Есть признаки частично нерабочей доставки в Telegram (серийные `Chat not found` в runtime-логах).
- Есть state-зависимые блокировки/дедупликации (deletion queue, collector state, debt stop state), которые могут останавливать повторные действия.
- В проекте отсутствует контур PDF-генерации как рабочий путь (по коду и поиску использования). убрать pdf из проекта полностью, не нужен.

## Вердикт по контурам

- IMAP / Queue / Pipeline: **Работает, но с риском**.
- Парсеры и HTML/JSON генерация: **Работает частично** (контур активен, но есть зоны «тихого skip» и неполной диагностики).
- PDF: **Не работает / не реализовано в рабочем потоке**.
- Telegram bot: **Работает частично**.
- CRM / Debt Stop / AI Collector / Manager Dialog: **Работает, но с риском state-конфликтов и зависимостей от внешних конфигов**.
- Registry / Contacts / State: **Работает, но с риском**.
- Scheduler / Runtime / Logs: **Работает, но с риском ложной видимости активности**.

## Критические риски (top)

1. **Неполная воспроизводимость среды**: без секретных конфигов и `.env` нельзя доказать консистентность ролей/доступов/маршрутизации.
2. **Скрытые отбрасывания входа**: часть IMAP-фильтров логируется в DEBUG, в INFO-потоке ветка выглядит «здоровой». 
3. **Ложноположительный успех в pipeline**: пустые выходы для ряда типов считаются нормой и не всегда эскалируются как ошибка.
4. **State-блокировки повторов**: ежедневные флаги и pending-состояния могут блокировать повторную отправку/эскалацию до ручного вмешательства.
5. **Частичная недоставка в Telegram**: систематические `Chat not found` подтверждают неполный охват целевых получателей.
